## ◈ What is POLYNOUS?

<div align="center">
<img width="80" src="https://raw.githubusercontent.com/Tarikul-Islam-Anik/Animated-Fluent-Emojis/master/Emojis/Objects/Telescope.png" alt="Telescope"/>
</div>

POLYNOUS is not a chatbot wrapper. It is a **neural research operating system** — a multi-agent AI platform where seven specialized agents orchestrate in sequence to produce research that is more thorough, more cited, and more honest about uncertainty than any single model response.

Where ChatGPT gives you one model's best guess, POLYNOUS assembles a research team: one agent searches the live web, one reads and condenses each source, one challenges the findings for contradictions, and one synthesizes a structured report — with citations, confidence scores, and identified limitations. For contested topics, three additional agents run a formal debate with an AI judge that scores both sides and declares a winner.

The platform is fully multi-user with cryptographic data isolation, supports bring-your-own API keys for Anthropic and OpenAI, ships with a live knowledge graph, semantic memory, PDF analysis, and a complete settings system — all in a single deployable open-source codebase.

## ◈ The Seven Agents

<div align="center">
<img width="80" src="https://raw.githubusercontent.com/Tarikul-Islam-Anik/Animated-Fluent-Emojis/master/Emojis/People/People%20with%20Bunny%20Ears.png" alt="Agents"/>
</div>

POLYNOUS operates two distinct pipelines — a four-agent **Research Pipeline** and a three-agent **Debate Pipeline** — orchestrated via LangGraph state machines.

<br/>

### Research Pipeline

<div align="center">
<img width="50" src="https://raw.githubusercontent.com/Tarikul-Islam-Anik/Animated-Fluent-Emojis/master/Emojis/Objects/Magnifying%20Glass%20Tilted%20Left.png" alt="Search"/>
</div>

```
  ┌─────────────┐     ┌──────────────────┐     ┌──────────────┐     ┌──────────────┐
  │ Search      │────▶│ Summariser       │────▶│ Critic       │────▶│ Writer       │
  │ Agent       │     │ Agent            │     │ Agent        │     │ Agent        │
  │             │     │                  │     │              │     │              │
  │ Queries     │     │ Condenses each   │     │ Cross-refs   │     │ Synthesizes  │
  │ Tavily for  │     │ source to key    │     │ claims and   │     │ final cited  │
  │ live web    │     │ insight points   │     │ scores conf. │     │ report       │
  │ results     │     │                  │     │              │     │              │
  └─────────────┘     └──────────────────┘     └──────────────┘     └──────────────┘
```

<br/>

| Agent | Responsibility | Model Used |
|:------|:--------------|:-----------|
| **Search Agent** | Queries Tavily for real-time web sources; extracts URLs, titles, and body text | Tavily API |
| **Summariser Agent** | Reads each source and extracts 3–5 key insight points per document | Claude / GPT-4o-mini |
| **Critic Agent** | Cross-references claims across sources; flags contradictions; assigns 0–100% confidence | Claude / GPT-4o-mini |
| **Writer Agent** | Synthesizes all summaries into a structured `Summary → Key Findings → Limitations → Confidence` report with inline citations | Claude / GPT-4o-mini |

<br/>

### Debate Pipeline

<div align="center">
<img width="50" src="https://raw.githubusercontent.com/Tarikul-Islam-Anik/Animated-Fluent-Emojis/master/Emojis/Objects/Hammer.png" alt="Judge"/>
</div>

```
  ┌─────────────┐     ┌──────────────────┐     ┌──────────────┐
  │ FOR         │────▶│ AGAINST          │────▶│ Judge        │
  │ Agent       │     │ Agent            │     │ Agent        │
  │             │     │                  │     │              │
  │ Builds      │     │ Counters with    │     │ Scores 1–10  │
  │ evidence-   │     │ opposing         │     │ declares     │
  │ backed case │     │ evidence         │     │ winner       │
  └─────────────┘     └──────────────────┘     └──────────────┘
```

<br/>

| Agent | Responsibility |
|:------|:--------------|
| **FOR Agent** | Constructs supporting arguments with cited evidence for the proposition |
| **AGAINST Agent** | Constructs opposing arguments with cited counter-evidence |
| **Judge Agent** | Evaluates both sides independently, scores each 1–10, provides detailed reasoning, declares winner |

### ⚙️ Settings & Key Vault

[![Encryption](https://img.shields.io/badge/Encryption-Fernet%20AES--128-7c3aed?style=flat-square&logo=letsencrypt&logoColor=white)]()
[![BYO](https://img.shields.io/badge/BYO-API%20Keys-f59e0b?style=flat-square&logo=keycdn&logoColor=white)]()

- **BYO API Keys**: save your own Anthropic, OpenAI, and Tavily keys — POLYNOUS uses them instead of the system keys
- Keys encrypted at rest using a Fernet key generated uniquely per user at registration
- Live key validation — POLYNOUS makes a real test API call before saving any key
- Masked key previews: `sk-ant-****-abcd` format
- Preferred LLM provider toggle (Anthropic ↔ OpenAI)
- Response style preference (persisted, applied to all future research)
- Full data export as structured JSON download
- Account management: password change, session revocation, full data reset

### Request Lifecycle

```
  1.  User submits query
        │
  2.  Frontend sends POST /ask-stream with Bearer token
        │
  3.  Auth middleware validates JWT → attaches user_id to request state
        │
  4.  BYO key resolver decrypts user's stored API keys (or falls back to system keys)
        │
  5.  LangGraph orchestrator initializes AgentState and begins pipeline
        │
  6.  Search Agent → Tavily API → returns sources with URLs and body text
        │
  7.  Summariser Agent → Claude/GPT → condenses each source to key points
        │
  8.  Critic Agent → Claude/GPT → cross-references claims → assigns confidence score
        │
  9.  Writer Agent → Claude/GPT → synthesizes structured report with citations
        │
  10. SSE events stream to frontend: start → progress (per agent) → tokens → end
        │
  11. On completion: results stored in Neo4j (graph), Pinecone (vectors), PostgreSQL (history)
        │
  12. Frontend renders Neural Synthesis Report with donut chart, findings, and citations
```

### Common Setup Issues

| Error | Cause | Fix |
|:------|:------|:----|
| `ModuleNotFoundError: magic` | Missing python-magic binary on Windows | `pip install python-magic-bin` |
| `Neo4j connection refused` | Wrong URI scheme | Ensure URI starts with `neo4j+s://` not `bolt://` |
| `Pinecone index not found` | Index auto-creates on first use | Wait 5–10 seconds after first request |
| `CORS error in browser` | `FRONTEND_URL` mismatch | Confirm env var matches exact frontend URL including port |
| `401 Unauthorized` on all routes | Token expired | Access tokens expire after 15 min — log in again |
| `422 Validation Error` | Malformed request body | Check `/docs` for exact schema |

## ◈ Security Model

<div align="center">
<img width="80" src="https://raw.githubusercontent.com/Tarikul-Islam-Anik/Animated-Fluent-Emojis/master/Emojis/Objects/Locked%20with%20Key.png" alt="Security"/>
</div>

POLYNOUS was designed with the assumption that it will handle sensitive research data across multiple users. Every layer of the stack includes explicit isolation and defense mechanisms.

<br/>

| Layer | Mechanism | Implementation Detail |
|:------|:----------|:----------------------|
| **Password storage** | bcrypt adaptive hashing | Work factor 12; unique salt generated per password; no plaintext ever written |
| **Session tokens** | JWT with dual-token model | Access tokens: 15 min expiry · Refresh tokens: 7 days, HttpOnly cookie, rotation on use |
| **Brute force protection** | Exponential lockout | 5 failed login attempts → 15 minute account lock; counter resets on success |
| **API key encryption** | Per-user Fernet keys | Unique Fernet key generated per user on registration; keys encrypted before PostgreSQL storage |
| **API key validation** | Live test before save | POLYNOUS makes a real minimal API call to validate any key before persisting it |
| **Input sanitization** | Multi-pattern middleware | Strips XSS payloads, SQL injection strings, shell injection, path traversal sequences on every request |
| **CORS policy** | Whitelist-based | Explicit origin whitelist — no `*` wildcard; configurable per environment |
| **Security headers** | Injection via middleware | `Content-Security-Policy`, `Strict-Transport-Security`, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff` |
| **Neo4j isolation** | Property-level user filtering | Every node written with `user_id` property; every read query includes `WHERE n.user_id = $user_id` |
| **Pinecone isolation** | Namespace scoping | Each user assigned a `user_{uuid}` namespace; all vector operations are namespace-scoped |
| **SQL injection prevention** | ORM parameterization | 100% of database queries written via SQLAlchemy ORM — no raw SQL string construction |
| **PDF security** | Multi-stage validation | File signature (magic bytes) check → embedded JavaScript detection → malware signature pattern scan |
| **Error handling** | Safe production messages | Stack traces never surfaced to clients in production; all errors return safe generic messages |
| **Dependency scanning** | Automated CVE detection | `pip-audit` + `Safety` run against all Python dependencies |

```bash
# Use a descriptive branch name
git checkout -b feat/semantic-caching
git checkout -b fix/neo4j-timeout-on-large-graphs
git checkout -b docs/update-api-reference
```

**3. Make your changes and commit**
```bash
git add .
git commit -m "feat: add semantic caching layer for repeated queries"
```

**Commit message prefixes:**

| Prefix | When to Use |
|:-------|:------------|
| `feat:` | New feature or capability |
| `fix:` | Bug fix |
| `docs:` | Documentation only |
| `refactor:` | Code restructuring with no behavior change |
| `test:` | Adding or updating tests |
| `chore:` | Dependency updates, config changes, maintenance |
| `perf:` | Performance improvements |
| `security:` | Security patches or hardening |

**4. Push and open a PR**
```bash
git push origin feat/semantic-caching
# Open a pull request on GitHub with a clear description of what changed and why
```

For significant changes, open an issue first to discuss the approach before writing code.
